구글 플레이 첫 출시 14단계 한눈에 보기

마지막 확인: 2026년 10월

처음 앱을 올릴 때 가장 힘든 점은 무엇을 어떤 순서로 해야 하는지 모른다는 것이에요. 아래 순서대로 하면 중간에 되돌아가는 일이 거의 없어요.

A. 한눈에 보기

#단계누가
0운영자(개인정보 보호책임자) 이름·문의 이메일 정하기나
1Play Console 개발자 계정 (25달러, 본인 인증)나
2개인정보처리방침·app-ads.txt를 공개 주소에 올리기나
3Play Console에서 앱 만들기나
4첫 AAB 직접 업로드 (딱 한 번)나
5업로드 키 지문 기록자동화 가능
6스토어 등록정보 (이름·설명·그래픽)자동화 가능
7앱 콘텐츠 양식 (콘텐츠 등급·타겟층·데이터 보안 등)나
8비공개 테스트 트랙 출시자동화 가능
9테스터 목록(구글 그룹) 연결나 + 자동화
10테스터 12명 × 14일 연속나 + 테스터
11프로덕션 액세스 신청나
12구글 심사·승인구글
13프로덕션 출시자동화 가능

B. 단계별로 꼭 알아 둘 것

0~2. 앱보다 먼저 준비할 것

개인정보처리방침에는 법에 따라 개인정보 보호책임자의 이름과 연락처가 들어가야 하고, 이메일은 스토어에도 공개돼요. 이걸 먼저 정해 두면 뒤 단계가 막히지 않아요. 방침 페이지는 누구나 열 수 있는 공개 주소여야 하고, AdMob을 쓴다면 스토어에 적는 개발자 웹사이트 주소 맨 위에 app-ads.txt가 있어야 해요. GitHub Pages(계정이름.github.io)를 쓰면 무료로 만들 수 있어요. → 개인정보처리방침 만들기

3~4. 앱 만들기와 첫 업로드

Play Console에서 앱을 만든 뒤, 첫 AAB는 화면에서 직접 올려야 해요. 자동화 도구(Play Developer API)는 이미 있는 앱에만 올릴 수 있기 때문이에요. 올리기 전에 AAB 검사기로 테스트 광고 ID와 서명을 확인하세요.

5. 업로드 키

Play 앱 서명을 쓰면 구글이 앱 서명 키를 보관하고, 나는 업로드 키로만 서명해요. 앱 무결성 화면의 업로드 키 SHA-256을 적어 두면, 다른 키로 서명한 파일을 올리는 실수를 미리 막을 수 있어요.

6~7. 스토어 등록정보와 앱 콘텐츠

앱 이름(30자), 짧은 설명(80자), 자세한 설명(4000자), 아이콘 512×512, 그래픽 1024×500, 휴대폰 스크린샷 2장 이상이 필요해요. → 스토어 등록정보 검사기. 앱 콘텐츠에서는 개인정보처리방침 URL, 광고 포함 여부, 콘텐츠 등급, 타겟층, 데이터 보안, 광고 ID 사용 여부를 모두 채워야 테스트 트랙에도 출시할 수 있어요. 타겟층에 어린이를 고르면 가족 정책이 적용되어 광고 설정이 크게 달라져요.

8~10. 비공개 테스트

2023년 11월 13일 이후 만든 개인 계정은 테스터 12명 이상이 14일 연속 참여해야 프로덕션을 신청할 수 있어요. 테스트 빌드에는 반드시 구글 테스트 광고 ID를 쓰세요. → 12명·14일 진행법, 계산기

11~13. 신청과 출시

14일이 지나도 저절로 열리지 않아요. 대시보드에서 프로덕션 액세스를 신청하면 테스트를 어떻게 했는지, 무엇을 고쳤는지 묻는 질문이 나와요. 구체적이고 사실대로 적으세요. 승인 후 프로덕션 빌드에는 내 실제 광고 ID가 들어가야 수익이 생겨요.

C. 자주 막히는 곳

  • "버전 코드가 이미 사용됨" — 같은 번호로 다시 올린 경우
  • 초안 앱이라 출시가 안 됨 — 첫 출시를 아직 확정하지 않은 경우
  • 광고가 안 나오거나 계정 경고 — 테스트/실제 광고 ID가 뒤바뀐 경우
