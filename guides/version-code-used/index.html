"버전 코드가 이미 사용되었습니다" 오류 해결

마지막 확인: 2026년 10월

AAB를 올렸는데 Version code 139 has already been used. Try another version code. 같은 메시지가 나오면 당황스럽죠. 원인은 하나예요. 그 번호를 이미 한 번 올렸기 때문이에요.

왜 생기나요?

  • Play는 한 번 올라간 versionCode를 다시 쓸 수 없게 해요. 출시를 취소했거나, 초안을 지웠거나, 다른 트랙(내부 테스트)에 올렸던 번호도 모두 "사용됨"으로 남아요.
  • 업데이트는 이전보다 큰 번호여야 기존 사용자에게 설치돼요. 같거나 작으면 업로드가 거절되거나 업데이트가 안 돼요.
  • versionName(예: 1.2.0)은 사람에게 보여 주는 이름일 뿐이고, Play가 비교하는 것은 versionCode(정수)예요.

지금 바로 해결하기

  1. Play Console > 테스트 및 출시 > App Bundle 탐색기에서 지금까지 올라간 가장 큰 versionCode를 확인해요.
  2. app/build.gradle의 versionCode를 그보다 1 큰 값으로 바꿔요.
  3. 다시 빌드(./gradlew bundleRelease)해서 새 AAB를 올려요.

올리기 전에 AAB 검사기에 파일을 넣고 "Play에 올라간 가장 큰 versionCode"를 적으면, 이 오류가 날지 미리 알려 줘요.

다시 안 생기게 하려면

방법 1. 빌드할 때 번호를 바깥에서 넣기

// app/build.gradle
versionCode providers.gradleProperty("VERSION_CODE").map { it.toInteger() }.getOrElse(4)

자동 빌드(예: GitHub Actions)가 Play에서 가장 큰 번호를 읽어 -PVERSION_CODE=다음번호로 넘기면, 사람이 번호를 관리할 필요가 없어요. 로컬 빌드는 적힌 기본값(4)을 그대로 써요.

방법 2. 규칙 정하기

자동화가 어렵다면 "올리기 전에 반드시 1 올리고 커밋" 같은 규칙을 정하세요. 테스트 트랙과 프로덕션은 같은 번호 공간을 쓰므로, 테스트용 빌드와 정식 빌드를 따로 만든다면 번호가 계속 올라가요.

헷갈리기 쉬운 경우

  • 업로드는 됐는데 출시를 안 눌렀어요 → 그래도 그 번호는 사용됨이에요.
  • 프로덕션에 실제 광고 ID로 새로 빌드했어요 → 비공개 테스트 빌드보다 큰 번호여야 해요.
  • versionName만 바꿨어요 → versionCode도 바꿔야 해요.
